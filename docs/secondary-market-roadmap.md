# 二级市场恢复记录

更新：2026-11-05

## 本次范围

恢复首页市场入口、我的页面交易管理入口及运用中基金的出售入口。交易管理分为购买申请和出售挂单，同一基金的多个挂单／申请分别保留，以挂单 id／processId 标识，不按 projectId 合并。

用户明确决定：签约操作和入金操作均暂缓。仅显示契约状态、当前用户待签提示、入金待确认提示；不调用签约、待机资金扣款或已汇款通知接口。一级市场钱包待入金列表限定 marketType=1，避免二级申请进入旧钱包流程。

## 合同依据与状态

依据 2026-11-04 至 11-05 Google Chat「谷町君开发小组」讨论，并核对 crowdfunding Swagger：
https://sit-admin.gutingjun.com/api/crowdfunding/v2/api-docs

- `/crowdfunding/user/apply/list` 支持 marketType：1 一级、2 二级、不传全部。一级认购页面传 1；二级购买列表传 2。
- 申请记录及挂单 applyList 保留 contractId、ecStatus、ecUserTodo。
- ecStatus：0 未签署、1 已签署、2 未生效、3 已生效；独立于申请审批状态。
- 挂单 status：VALID／INVALID。
- 购买申请 status：0 待审核、1 驳回、2 审核通过／待入金确认、3 入金确认／购买成功、4 过期、5 撤回。
- `/crowdfunding/secondary/market/available` 提供 availableNum 和 investmentUnit；SDK 适配保留，但当前从运用详情出售不再依赖此接口。

## 已实现

- 运用详情顶部大卡片下方新增出售中挂单入口，按当前账号、当前 projectId 与购买 processId 对应的 fromProcessId 筛选 VALID 且未售罄的挂单；可进入既有挂单详情。

- 运用详情数量区并列展示投资口数、剩余口数（investNumValid）、可售口数（investNumRemaining）；出售填写和确认步骤明确提示当前订单最多可出售口数。

- 保留原有运用列表和详情显示／取数逻辑。仅出售入口直接使用所点击记录的 projectId、processId 和 investNumRemaining。撤销 available 接口交叉匹配及选择其他持仓的逻辑；提交保持同一 fromProcessId，最终库存由创建接口校验。

- SDK 统一解析筛选参数、契约字段和可出售持仓；App 通过 repository/usecase 使用。
- 市场仅查询 VALID 挂单；出售列表按当前用户查询，购买列表查询当前用户二级申请。账户变更重建列表。
- 分页、下拉刷新、回到前台及详情返回刷新；刷新失败保留已有内容。
- 详情重新查询挂单／申请，不使用路由快照授权操作。接口没有单条挂单查询，暂用分页定位。
- 购买提交前重新校验挂单有效性、库存、单价及非本人挂单；出售按当前记录的剩余口数校验输入，后台创建接口校验最终可售库存。提交期间防重复点击。
- 提交购买后显示“申请已提交”；保留撤回购买及取消挂单操作，成功后刷新关联数据。
- 四语言文案已生成；业务状态映射及业务卡片留在 App feature 内。

## 2026-11-09 My Page 売買管理

My Page 快捷入口进入交易管理，默认「ファンドを売る」。按[测试站的管理区块](https://testoa.gutingjun.com/mypage#secondary)使用 AppFilterBar 和 App 基金卡片。筛选切换回到第一页，每页 10 条。

- 出售从 available 读取当前账户的逐笔持仓，先过滤可售口数大于零的记录再本地分页。出售沿用该笔购买的 processId 和口数上限。
- 购买按页查询 VALID 挂单，显示剩余口数大于零的记录。点击进入 App 的市场详情与购买流程。
- 売買履歴默认「売却」，以当前用户 ID 查询所有挂单；「応募」以 marketType=2 查询购买申请。详情保留状态、合同信息与已有撤销流程。售出或购买提交成功后进入相应履历。
- 页面仅在进入后读取所选区块。分页依据接口总数，保留同一基金下不同订单的独立记录。
